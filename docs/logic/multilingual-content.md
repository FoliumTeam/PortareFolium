# 언어별 콘텐츠와 화면 언어

## 목적과 선택 순서

- 지원 언어: 한국어 `ko`, 영어 `en`, 일본어 `ja`
- 공개 선택 순서: 유효한 `lang` → 저장한 화면 언어 → 브라우저의 지원 언어 우선순위 → 영어
- 공개 주소의 `lang`: `kr | en | ja`, `kr`만 내부 `ko`로 변환. 지원하지 않는 값은 기존 자동 선택
- 공개 Header의 직접 선택: 선택 저장, 현재 주소의 `lang`만 제거, 나머지 query·hash 보존 후 전체 재조회. 현재 언어 재선택도 같은 처리
- 강제 주소 접속만으로 기존 선택 쿠키 변경 없음. 언어 파일 준비 실패 시 주소·선택 쿠키 보존
- 관리자 화면 언어와 콘텐츠 입력 언어: 독립 선택

예: 한국어 화면에서 영어 이력서 편집 가능. 화면 언어 변경 뒤에도 입력 중인 영어 자료와 미저장 내용 보존. 콘텐츠 언어 변경은 미저장 내용이 없는 상태에서만 허용.

## 주소와 공개 캐시

- 사용자 주소: 기존 `/{jobField}/resume`, `/{jobField}/portfolio/{slug}` 형식 유지
- 강제 언어 링크 예: `/web/portfolio?lang=en`, 공개 내부 이동·검색 결과·블로그 필터에서 유효한 `lang` 유지
- 외부 링크·다운로드·관리자·API 주소에는 강제 언어 전파 제외
- 내부 경로: Proxy에서 `/{locale}/...`로 변경, 브라우저 주소에는 언어 경로 노출 제외
- 직접 내부 경로 접근: 기존 공개 주소로 이동
- 공개 Server Component: 명시적인 경로 언어 사용, 요청 쿠키·헤더 조회 제외
- 공개 페이지: 정적 생성과 1시간 ISR 적용
- 데이터 캐시: 언어를 키 인수로 포함, `public-content` 태그 공유
- 콘텐츠 변경: 기존 주소와 세 언어 내부 경로·공개 데이터 태그 함께 갱신
- 상세 사전 생성: 모든 언어의 완전한 `locale`·`jobField`·`slug` 조합 반환

번역이 없는 상세: 안내 문구 없이 같은 직무·지원 공유 범위의 상위 목록으로 클라이언트 이동. 기존 query·hash 보존, 다른 언어 원문 대체 표시 제외. query 관찰만 작은 Suspense 영역에 격리해 정적 본문 유지.

공개 검색: 표시 언어를 명시한 서버 조회, 기존 호출의 저장 언어 기본값 호환. 공개 상태·직무 필터와 결과 주소의 직무 경로 유지.

## 저장 범위

| 자료                             | 한국어                   | 영어·일본어                 |
| -------------------------------- | ------------------------ | --------------------------- |
| 이력서                           | `resume_data`, `lang=ko` | 같은 테이블의 `lang=en/ja`  |
| 소개·글·포트폴리오·독서          | 기존 테이블              | 대응하는 `_i18n` 테이블     |
| 편집 상태·글 본문 조각·수정 이력 | 기존 테이블              | 언어별 `_i18n` 테이블       |
| 지원용 공유 사본                 | `application_profiles`   | `application_profiles_i18n` |
| 사이트 표시 문구                 | `site_config`            | `site_config_i18n`          |

- 독립 행: 같은 slug·공유 토큰 사용 가능, 자료와 공개 상태는 언어별 분리
- 새 번역: 빈 자료 또는 명시적인 비공개 복사로 시작
- 한국어만 작성한 경력·글·포트폴리오: 영어·일본어 조회 결과에서 제외
- 사이트 구조·색상·기능 설정: 공통값 유지, 제목·설명·탐색 문구는 언어별 값
- 복사: 대상 자료가 이미 존재하면 덮어쓰기 거부
- 공유 사본: 같은 토큰에서 선택 언어의 공개 사본 조회, 원문 사본 대체 표시 제외

## 관리자 입력 보호

- 화면 선택 쿠키: `portarefolium_locale`
- 콘텐츠 선택 쿠키: `portarefolium_content_locale`
- 탭별 입력 언어: `sessionStorage`, 다른 탭의 쿠키 변경과 분리
- 서버 작업: 호출 시 캡처한 `__contentLocale` 전달
- 진행 중 저장: 완료 후 콘텐츠 언어 변경
- 미저장 내용: 콘텐츠 언어 선택 차단, 화면 언어 변경 허용
- 본문 분할 업로드: 전체 작업에서 동일한 콘텐츠 언어 헤더 유지
- 공통 언어 메뉴: 로컬 평면 국기·고유 언어명·선택 표시의 shadcn DropdownMenu, 키보드·Escape·초점 복귀 지원
- 관리자 표시 언어: Header의 ThemeToggle과 로그아웃 사이. 콘텐츠 입력 언어는 별도 영역 유지
- 초기 탭: 주소 hash 확인 후 메인 화면 mount, 다른 탭 직접 진입의 무관한 초기 조회 제외

## 현재 항목의 언어 사본

- 원본: 현재 입력 언어의 저장 문서. 이력서·소개는 전체 문서, 포트폴리오·글·독서·지원 프로필은 현재 항목 하나
- 중앙 Dialog: 콘텐츠 유형·원본 제목·원본 언어와 대상 언어 표시. 사용자 작성 제목은 원문 보존
- 대상 선택: 원본을 제외한 두 언어, 처음에는 미선택. 새 사본은 비공개, 기존 대상이 있으면 복사 거부
- 입력 보호: 미저장 변경·진행 중 작업·중복 제출 차단, 제출 직전 원본 언어 재확인. 완료 뒤 원본 화면과 입력 언어 유지
- 공개 상태: 이력서·소개 편집 화면 내부에서 조작. 미저장 문서·내용 변경·진행 중 작업에는 상태 변경 차단
- 저장 보호: 빈 이력서 초기 행만 JSON 조건부 갱신과 정확히 1행 확인. 소개의 현재 앱 최초 생성 경로는 공통 UUID 사용, 기존 행 식별자 보존
- 오류 보호: 복사 본문·지원 기준 자료는 엄격한 조회와 분할 개수·순서·checksum·hash 검사. 조회 실패를 빈 사본으로 대신 저장하는 처리 제외
- 지원 기준 자료의 게시물: 분할 본문 전체 복원 후 내부 `id`·`job_field` 제거. 기본 공개 읽기의 기존 대체 동작 유지
- 구버전 앱의 동시 생성이나 DB 직접 삽입까지 소개의 단일 행을 강제하는 새 DB 제약은 이번 범위 밖

## MCP와 자료 이동

- 콘텐츠 도구의 `lang`: `ko | en | ja`, 생략 시 기존 `ko`
- 콘텐츠 수정 전 조회, 수정 후 같은 언어 재조회
- DB 백업과 Orireki 내보내기: 현재 화면 언어와 독립적으로 모든 언어 포함
- Orireki 묶음: 한국어 `settings` 유지, `lang`·`settingsByLanguage` 추가
- 번역·비공개 자료 포함: `version: 2`, 언어·공개 상태를 무시하는 구형 가져오기 거부
- 공개 한국어만 포함: 기존 `version: 1` 호환 유지
- 번역 콘텐츠 `sourceId`: 언어 접두사 포함, 기존 한국어 식별자 유지
- 분할 본문: 언어·수정 이력별 순서와 해시 검증, 손상 시 경고와 원본 조각 보존
- 인증·운영 토큰: 콘텐츠 이전 묶음에서 제외
- 구형 Orireki로 모든 언어를 실제 복원하는 동작: 미지원. 형식 2 지원 소비자 구현과 별도 연결 검증 필요

## 이미지 보존

- 새 번역 이미지: 언어별 경로 사용
- 기존 원본 이미지: 번역 자료에서 같은 주소 참조 가능
- 삭제·이동: 전체 언어·편집 상태·본문 이력·공유 사본·사이트 설정의 참조 확인
- 조회 실패·상한 초과: 삭제 중단
- 본문 조각의 이미지 주소: 페이지 경계에 걸친 조각까지 합쳐 확인
